어드민 서비스란

신규 패키지 시스템은 상품과 예약과 공급사 연동과 검색을 별도 서비스로 분리한다. 담당자의 업무는 여러 서비스에 걸쳐 이어지므로 서비스별로 도구를 두면 업무 하나를 처리하려고 여러 시스템에 접속해야 한다.

어드민 서비스는 서비스들의 관리 기능을 담당자 업무 순서대로 연결한 내부 시스템이다. 역할이 다른 담당자가 같은 시스템을 사용하므로 역할별로 사용할 화면과 기능을 판정한다.

담당자의 업무는 다음 순서로 이어진다.

  • 항공과 호텔과 투어 아이템을 조합해 상품을 구성하고 출발일별 판매 상태를 관리한다.
  • 외부 여행사에서 수집한 상품의 지역과 취소 규칙과 문구를 검수한다.
  • 예약을 조회하고 여행자 정보와 취소를 처리하며, 공급사에 요청한 예약(공급 예약)이 실패하면 같은 화면에서 다시 실행한다.
  • 취소와 할인을 기안서로 상신하면 승인 권한이 있는 담당자가 승인하거나 반려한다.

구성

어드민 서버는 화면을 제공하면서 페이지 권한을 판정하고 경로별 위임 규칙으로 요청을 서비스 API에 전달한다. 담당자 식별은 사내 SSO가 담당한다.

어드민 서버가 경로별로 요청을 전달하므로 브라우저는 어드민 서버 주소만 호출한다. 응답을 변환하거나 조합하지 않으므로 결과 조합과 실패 표시는 화면 코드에 남는다.

서비스 API에는 API마다 허용 역할을 어노테이션으로 지정한다.

권한 판정 표

초기 구성은 페이지마다 서버 렌더링 함수에서 그룹 존재 여부를 확인하고 일부 화면만 관리자 등급을 추가로 확인했다. 기획 권한 문서는 역할마다 허용 페이지를 다르게 정하고 같은 페이지 안의 버튼까지 역할별로 구분하므로 초기 구성으로 표현하지 못했다.

기획 요구는 페이지별 판정의 공통화와 기존 등급 기능의 활용 가능성을 함께 제시했다. 권한을 변경할 때 수정하는 위치는 방식마다 다르다.

방식권한 변경 시 수정 위치한계
페이지별 판정 유지페이지와 버튼 코드 전체권한 규칙이 코드 전체로 분산되어 기획 권한 문서와 대조하기 어렵다.
기존 등급 기능 활용그룹별 등급 목록과 화면의 등급 확인역할마다 허용 페이지가 다르면 등급 확인을 화면마다 다시 작성한다.
판정 표 분리(현재)판정 표역할과 페이지가 늘어나면 판정 표가 길어진다.

판정 표는 코드에 두는 권한 설정 파일이고 권한 판정은 다음 단계로 나뉜다.

  • 그룹 역할 표가 환경마다 다른 사내 인증 그룹을 역할로 변환한다.
  • 역할별 허용 목록은 페이지 표와 메뉴 표와 버튼 표로 분리한다.
  • 어드민 서버가 페이지를 판정하고 화면 컴포넌트가 메뉴와 버튼을 판정한다.

그룹 역할 표에 없는 그룹과 버튼 표에 없는 버튼은 허용하지 않는다.

페이지 표는 역할마다 전체 페이지를 같은 순서로 나열하고 허용하지 않는 줄을 주석으로 남긴다. 그래서 역할 사이의 차이를 줄 단위로 비교하고 기획 권한 문서와 대조한다.

같은 페이지 안의 기능은 버튼 식별자로 구분한다. 권한 컴포넌트가 식별자로 허용 역할을 조회하고, 기획 요구에 따라 허용되지 않은 역할에는 버튼을 비활성으로 표시한다.

버튼 식별자는 문자열이므로 버튼 표와 일치하지 않아도 빌드에서 검출되지 않는다. 불일치한 버튼은 모든 역할에 비활성으로 표시되어 허용 범위가 넓어지지 않으며, 기획 QA에서 같은 오류를 검출해 버튼 표를 수정한 사례가 있다.

역할 정의와 그룹 역할 표는 서비스에도 각각 존재하므로 역할을 추가하면 어드민과 서비스를 함께 수정한다.

권한 전환 순서

신규 사내 인증 그룹 생성과 사용자 이동은 판정 코드 배포와 별도 작업이었다. 기존 그룹 일부는 제한된 역할로 변환되었으므로 판정 코드만 적용되면 아직 이동하지 않은 담당자의 기능이 차단되는 상태였다.

판정 코드는 개발 환경에 먼저 배포되었고 신규 그룹 생성과 사용자 이동은 그 뒤의 작업으로 남아 있었다. 기존 담당자의 기능이 차단되지 않도록 기존 그룹에는 전체 권한이 부여되었다.

판정 코드 배포는 그룹 작업을 기다리지 않았지만 전환 기간에는 기존 그룹에 세분화된 권한이 적용되지 않았다.

대량 알림톡 발송

담당자는 홈쇼핑 방송으로 접수한 고객에게 상품 안내를 메신저 알림(알림톡)으로 발송한다. 초기 구성은 상품 서비스 호출 하나가 선택한 수신자 전체를 순차로 전송하고 수신자마다 상품 정보를 다시 조회했으며, 대량 발송에서 전송이 완료되지 않았다.

현재는 어드민 화면이 수신자를 일정 건수로 분할해 순차 호출하고, 상품 서비스가 호출 안의 수신자를 병렬로 전송한다. 상품 정보는 호출마다 한 번 조회하고 화면은 호출별 결과를 합산해 표시한다.

분할 호출을 어드민 화면이 실행하므로 담당자는 발송이 끝날 때까지 화면을 유지해야 한다. 대신 발송 작업의 상태를 저장하는 구조를 추가하지 않고 API 응답 형식을 유지한다.

전송에 실패하거나 결과가 불확실한 수신자는 건수로만 집계되고 건별 상태가 갱신되지 않으므로 재발송 여부는 담당자가 판단한다.

맡은 범위

여러 개발자가 스프린트 단위로 작업을 나누어 개발하고 PR 리뷰로 함께 개선했다. 다음 항목을 직접 개발했다.

  • 페이지별 권한 판정 코드를 제거하고 판정 표와 권한 컴포넌트를 작성했다.
  • 기획 권한 문서에 페이지와 메뉴와 버튼 제어가 섞여 있어 QA 누락 위험이 있다는 점을 전달했고, 기획 QA 지적을 판정 표에 반영했다.
  • 판정 코드를 먼저 배포하고 기존 그룹에 전체 권한을 부여하는 전환 순서를 적용했다.
  • 할인 기안서의 상신과 승인과 반려 화면을 작성했고 예약 서비스의 할인 기안서 API 일부를 작성했다.
  • 홈쇼핑 예약자 화면의 담당자 지정과 알림톡 발송을 작성했다.
  • 대량 알림톡 발송을 분할 순차 호출과 서비스 내 병렬 전송으로 수정하고 개발 환경 테스트로 전송 완료를 확인했다.

  • 어드민 서버의 경로별 위임 구성
  • 서비스 API의 역할 지정
  • 예약 상세의 공급 예약 재실행 화면
