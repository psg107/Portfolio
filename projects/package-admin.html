어드민 서비스란

어드민 서비스는 패키지 여행 담당자가 상품 구성부터 취소 승인까지 한곳에서 진행하는 내부 시스템이다. 업무마다 서비스가 나뉘어 있으므로 서비스별로 도구를 두면 업무 하나를 처리하려고 여러 시스템에 접속해야 한다.

역할이 다른 담당자가 같은 시스템을 사용하므로 사용할 화면과 기능을 역할별로 구분한다.

구성

어드민 서버는 경로에 따라 요청을 전달할 뿐 응답을 조합하지 않으므로 여러 서비스의 결과를 묶는 일은 어드민 화면이 담당한다.

역할별 권한 판정

초기 구성은 페이지마다 담당자의 사내 인증 그룹이 있는지 확인하고 일부 화면만 관리자 등급을 추가로 확인했다. 기획 권한 문서가 역할마다 허용 페이지를 다르게 정하고 같은 페이지의 버튼까지 구분하면서 이 구성으로는 표현하지 못하게 되었다.

기획 요구는 기존 등급 기능의 사용도 제시했지만 등급은 화면마다 확인하는 구조여서 역할별 허용 페이지가 다르면 확인 코드를 화면마다 재작성해야 한다. 현재 구성은 역할별 허용 목록을 코드 안의 판정 표에 모은다.

역할이 정해지면 판정 표로 페이지부터 버튼까지 허용을 각각 판정한다.

버튼은 문자열 이름으로 표를 조회하므로 이름이 어긋나도 빌드에서 검출되지 않는다. 어긋난 버튼은 모든 역할에 비활성으로 표시되어 허용 범위가 넓어지지 않으며 실제로 기획 QA에서 같은 오류를 검출해 표를 수정했다.

대량 알림톡 발송

담당자는 홈쇼핑 방송으로 접수한 고객에게 상품 안내를 카카오 알림톡으로 발송한다. 초기 구성에서 대량 선택 발송이 완료되지 않은 일이 있어 현재는 수신자 분할을 어드민 화면이, 병렬 전송을 상품 서비스가 담당한다.

호출 반복을 어드민 화면이 담당하므로 발송 작업의 상태를 저장하는 구조 없이 기존 API 응답 형식이 유지되고, 담당자는 발송이 끝날 때까지 화면을 유지해야 한다.

맡은 범위

여러 개발자가 스프린트 단위로 작업을 나누어 개발하고 PR 리뷰로 함께 개선했다. 다음 항목을 직접 개발했다.

  • 페이지별 권한 판정 코드를 제거하고 판정 표와 버튼 권한 컴포넌트를 작성했다.
  • 기획 QA 지적을 판정 표에 반영했다.
  • 홈쇼핑 고객 알림톡 발송 화면을 작성하고 대량 발송을 분할 호출과 병렬 전송으로 수정했다.

다음 영역은 다른 개발자가 개발했다.

  • 어드민 서버의 경로별 요청 전달 구성
  • 예약 상세의 공급 예약 재실행 화면
