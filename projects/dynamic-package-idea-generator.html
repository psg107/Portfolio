여행 서비스 아이디어 생성 시스템이란

여행 서비스를 기획할 때는 후보 기능을 많이 모은 뒤 구현할 것을 선별해야 하고, 후보를 사람이 일일이 작성하고 평가하는 데 시간이 든다.

이 시스템은 LLM으로 기능 아이디어를 요구사항 문서(PRD) 형태로 주기적으로 생성하고, 평가 점수와 유사 아이디어를 함께 표시한다. 사용자가 즐겨찾기와 삭제로 선별한 결과는 다음 생성에 전달된다.

전신은 사내 AI 해커톤 팀의 아이디어 발굴용 생성기다. 이 시스템은 대상을 여행 서비스 기획으로 변경하고 중복 판정과 평가와 피드백 경로를 새로 갖춘다.

구성

생성 요청은 스케줄과 화면에서 발생하고 모두 작업으로 저장된다. 생성된 아이디어는 임베딩과 평가를 거쳐 상세 화면에 표시되고, 사용자의 선별 결과는 다음 생성에 전달된다.

스케줄 요청은 항상 에이전트 방식으로 생성한다.

생성 방식

두 방식은 기존 아이디어와 사용자의 선별 결과를 읽는 주체가 다르다. 에이전트 방식은 모델이 도구를 호출해 필요한 자료를 조회하고, 단순 방식은 코드가 자료를 프롬프트에 포함해 LLM을 직접 호출한다.

자료에이전트 방식단순 방식
기존 아이디어키워드 검색 도구와 의미 검색 도구로 조회한다.최근 아이디어 목록을 프롬프트에 포함한다.
즐겨찾기즐겨찾기 조회 도구로 최근 10건까지 읽는다.전달되지 않는다.
저평가와 삭제저평가 조회 도구로 5점 이하와 삭제 사례를 읽는다.삭제 사례 20건까지 프롬프트에 포함한다.
저장 후 비교최근 50건과 임베딩을 비교한다.수행하지 않는다.

화면 요청의 기본값은 단순 방식이고 사용자가 지정하면 에이전트 방식으로 생성한다.

에이전트 방식의 조회는 모델의 판단으로 일어나므로 프롬프트의 지시만으로 호출을 강제하지 못한다. 단순 방식은 자료의 전달이 코드로 보장되는 대신 전달 범위가 프롬프트에 포함한 최근 목록으로 제한된다.

중복 판정

주기적으로 생성하면 표현만 다른 제안이 반복된다. 예를 들어 "출장 동선 효율성 점수 표시 기능"과 "출장 동선효율 점수 시각화 기능"은 제목이 다르지만 같은 제안이다.

이 시스템은 제목과 요약의 임베딩을 PostgreSQL에 저장하고 애플리케이션에서 코사인 유사도를 계산한다. 의미가 같은 제안을 찾는 다른 방식과 비교하면 동작과 제약이 다음 표처럼 다르다.

방식동작제약
프롬프트 목록최근 제목과 요약을 프롬프트에 포함한다.표현이 다른 중복의 판단을 모델에 의존한다.
벡터 DB전용 저장소에서 유사 벡터를 검색한다.저장소 서버를 함께 실행해야 한다.
코사인 비교저장된 벡터를 읽어 애플리케이션에서 계산한다.비교할 때마다 대상 벡터를 읽고 파싱한다.

에이전트 방식의 판정은 생성 전과 생성 중과 저장 후로 나뉜다. 단순 방식은 저장 후 비교를 수행하지 않고 상세 화면의 구간 표시만 적용된다.

조건 순차 선택은 길이가 다른 고객 유형과 기획 단계와 주제와 불편 유형 목록을 순서대로 조합해 생성 조건을 코드에서 결정한다.

의미 검색의 유사도 기준은 도구 기본값이 0.7이고 모델이 호출할 때 지정하며, 기록이 남은 실행 구간의 호출은 모두 0.5에서 0.65를 지정한다. 저장 후 비교는 코드에 고정된 0.85 기준으로 동작한다.

0.85 이상이어도 저장을 차단하지 않으므로 표현만 다른 제안은 사용자가 삭제하기 전까지 남는다. 저장된 아이디어에서 추출한 유사 쌍 자료에는 0.85 이상인 쌍이 6개 있고 그중 1개는 제목까지 같다.

저장 후 비교와 의미 검색은 각각 최근 50건과 최근 100건만 대상으로 한다. 더 오래된 아이디어와의 중복은 자동으로 판정하지 못하고 상세 화면에서 사용자가 확인한다.

피드백 반영

전신인 생성기는 사람이 프롬프트를 수정해 방향을 조정했고, 품질 평가 자동화와 피드백 기반 프롬프트 개선은 미해결 과제였다. 이 시스템은 즐겨찾기와 LLM 평가와 삭제 사유를 저장해 생성 방식별 경로로 다음 생성에 전달한다.

삭제 사례는 사유가 있어야 다음 생성에 전달되고 사유 입력은 선택이다. 사유 없이 삭제하면 LLM이 최근 아이디어 목록과 비교해 중복이나 비현실성 같은 사유를 1~2문장으로 추론한다.

다음 생성은 추론한 사유와 사용자가 입력한 사유를 구분하지 않고 읽으므로 사용자의 실제 의도와 다른 사유가 전달될 수 있다. 평가도 제목과 요약과 분류 정보만 읽으므로 저평가 사례의 점수는 본문 품질을 반영하지 않는다.

에이전트 응답에서 JSON 블록 앞의 서술은 사고 과정으로 저장되고, 의미 검색 결과에 500자까지 포함되어 다음 에이전트에 전달된다. 피드백으로 생성 품질이 달라졌는지 전후로 측정한 기록은 없다.

생성 작업 상태

기록이 남은 실행 구간에서 에이전트 생성은 건당 4분에서 11분이 소요되어 HTTP 요청을 유지한 채 처리하기 어렵다. 스케줄 실행에는 응답을 기다리는 호출자도 없다.

생성과 평가와 삭제 사유 추론은 작업 테이블에 상태와 함께 기록되고 코루틴에서 실행된다. 메시지 큐를 사용하면 브로커를 함께 실행해야 하고, 이 구성은 브로커 없이 PostgreSQL 작업 테이블로 상태를 관리한다.

재시작 복구는 실행 중간 상태를 복원하지 않으므로 처리 중이던 생성 작업을 처음부터 다시 실행하고, 중단된 작업만큼 LLM 호출 비용이 다시 발생한다.

작업 상태는 조회 후 저장으로 변경되므로 서버를 여러 대로 늘리면 같은 작업을 중복 실행할 수 있다. 시스템은 PC 한 대에서 실행되고 이 범위 안에서 동작한다.
