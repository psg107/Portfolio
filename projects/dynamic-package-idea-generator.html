여행 서비스 아이디어 생성 시스템이란

여행 서비스를 기획할 때는 기능 아이디어를 많이 모은 뒤 구현할 것을 선별해야 하고, 사람이 일일이 작성하고 평가하는 데 시간이 든다. 여행 서비스 아이디어 생성 시스템은 PC 한 대에서 실행되고, LLM으로 기능 아이디어를 요구사항 문서(PRD) 형태로 주기적으로 생성해 평가 점수와 유사 아이디어를 함께 표시한다.

전신인 사내 AI 해커톤용 생성기는 최근 아이디어 목록을 프롬프트에 포함해 중복 판단을 모델에 맡겼고, 품질 평가와 피드백 반영은 과제로 남았다. 생성 방식은 모델이 도구로 자료를 조회하는 에이전트 방식과 코드가 프롬프트에 자료를 포함하는 단순 방식이 있고, 에이전트 방식은 시간이 더 걸리며 화면 요청에서는 사용자가 지정할 때만 실행된다.

구성

중복 판정

"출장 동선 효율성 점수 표시 기능"과 "출장 동선효율 점수 시각화 기능"은 제목이 다르지만 같은 아이디어다. 표현이 다른 중복을 찾기 위해 제목과 요약을 의미 벡터(임베딩)로 변환해 PostgreSQL에 저장하고, 전용 벡터 DB 서버 없이 비교할 때마다 대상 벡터를 읽어 유사도를 계산한다.

저장 후 자동 판정은 에이전트 방식에만 적용되고 최근 아이디어만 비교한다. 단순 방식의 중복과 더 오래된 아이디어와의 중복은 상세 화면에서 사용자가 확인한다.

선별 결과 전달

사용자의 즐겨찾기와 삭제, LLM의 평가 점수는 다음 생성의 자료로 전달되고 전달 경로는 생성 방식마다 다르다.

긴 생성 작업

에이전트 생성은 실행 기록 기준으로 건당 4분에서 11분이 걸려 HTTP 요청을 유지한 채 처리하기 어렵다. 생성 요청은 PostgreSQL 작업 테이블에 상태와 함께 기록되고 백그라운드에서 실행된다.

메시지 큐 브로커 없이 상태를 조회한 뒤 저장해 변경하는 구조여서 서버를 여러 대로 늘리면 같은 작업이 중복 실행될 수 있다. 재시작 복구는 처리 중이던 작업을 처음부터 다시 실행하고, 그만큼 LLM 호출 비용이 다시 발생한다.
