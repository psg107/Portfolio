통합 검색 서비스란

통합 검색 서비스는 고객이 고른 조건으로 패키지 상품을 검색하고 조건에 맞는 출발일 중 최저가를 표시하는 서비스다. 같은 상품도 출발일마다 가격과 항공편이 다른데 사내 공통 검색 서비스의 색인은 상품 수준의 값만 다루므로 출발일 수준의 값은 이 서비스가 검색 시점에 반영한다.

상품 약 2만 개를 다루면서 검색 요청마다 출발일별 값을 조회하고 계산하던 때 약 8초였던 응답 시간은 아래 구조를 적용한 뒤 1초 미만으로 단축되었다.

구성

검색 세션은 사내 공통 검색 서비스가 후보 상품을 선정해 생성하는 결과 집합이고, 이후 요청은 세션 식별자로 같은 결과 집합을 조회한다. 통합 검색 서비스가 계산한 최저가를 검색 세션에 전달하면 세션이 그 값으로 필터링하고 정렬한다.

출발일 값 조회 구조

최저가 계산에는 상품 서비스가 관리하는 출발일별 값이 필요하고, 조회 구조는 상품 서비스 호출에서 Redis를 거쳐 MongoDB로 변경되었다. Redis 구조는 날짜 범위로 최저가 출발일을 먼저 선택한 뒤 항공사 조건을 비교하므로 다른 출발일이 조건을 충족해도 상품이 결과에서 제외된다.

검색 요청이 상품 서비스를 호출하지 않는 대신 상품 변경은 동기화가 끝난 뒤 검색에 반영되고, 필터 조건별 인덱스도 별도로 관리한다.

출발일 조건의 반영

지역과 테마는 검색 세션을 생성할 때 적용되지만 항공사와 가격은 출발일마다 달라 색인으로 판정하지 못한다. 그래서 통합 검색 서비스가 MongoDB의 값으로 후보 상품별 최저가를 계산해 검색 세션에 전달한다.

중복 세션 생성 방지

세션 생성은 외부 호출과 집계를 포함하므로 통합 검색 서비스는 검색 조건을 키로 세션 식별자를 Redis에 저장해 재사용한다. 캐시가 빈 조건에 요청이 동시에 집중되면(Cache Stampede) 같은 세션 생성이 반복되므로 생성 중이라는 표시를 먼저 저장한 요청만 세션을 생성하고, 나머지 요청은 생성이 끝날 때까지 결과 없이 대기한다.

만료 전 갱신

만료가 가까운 캐시에 요청이 도달하면 기존 식별자를 반환한 뒤 백그라운드에서 캐시를 교체하므로 만료 뒤 첫 요청이 세션 생성 비용을 모두 부담하는 경우가 줄어든다.

맡은 범위

여러 개발자가 스프린트 단위로 작업을 나누어 개발하고 PR 리뷰로 함께 개선했고, 검색 영역은 주 담당으로 2025.01까지 집중해 개발한 뒤 2025.12까지 수정에 참여했다. 다음 항목을 직접 개발했다.

  • 서비스 초기 코드와 검색 API를 개발했다.
  • 구패키지 시스템과 Kotlin으로 새로 개발한 신규 패키지 시스템의 상품을 같은 색인 형식으로 변환하는 경로와 동기화를 다른 개발자와 함께 개발했다.
  • 출발일 값의 조회를 상품 서비스 호출에서 Redis와 MongoDB로 변경하고 필터 조건별 인덱스를 구성했다.
  • 검색 세션에 값을 전달하는 흐름과 MongoDB 집계의 분할 병렬 처리를 개발했다.
  • 생성 중 표시를 조건부 저장으로 변경하고 갱신 락과 만료 전 갱신을 개발했다.

다음 영역은 다른 개발자가 개발했다.
