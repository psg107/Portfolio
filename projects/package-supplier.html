공급사 연동 서비스란

외부 여행사의 패키지 상품을 자사 판매 채널에서 함께 판매하면 외부 여행사가 변경한 가격과 좌석과 판매 상태를 자사 판매 정보에 계속 반영해야 한다. 모두투어는 변경을 통지하지 않으므로 공급사 연동 서비스가 모두투어의 상품을 매일 읽어 변경을 판정하고 결과를 상품 서비스에 전달한다.

모두투어 상품은 기초상품과 출발상품으로 구성된다. 기초상품은 여행 상품 하나이고 출발상품은 기초상품을 출발일과 항공편별로 나눈 판매 단위다.

출발상품은 모두투어 기준 약 280만 건이고 매일 4만 건 이상 변경되는 규모로 집계되었다.

구성

공급사 연동 서비스는 코드 저장소를 나누지 않고 같은 코드를 실행 프로필로 나누어 수집과 조회와 배치를 실행 단위별로 배포한다. 동기화 배치는 매일 모두투어 목록을 저장된 상품과 비교해 변경된 출발상품만 수집을 요청하고, 항공편별 대표 출발상품 1건의 상세를 Redis에 템플릿으로 저장한다.

수집 서비스는 템플릿의 날짜를 이동해 출발상품을 조립하고 출발일별 판매 정보를 갱신한 뒤 완료 이벤트를 AWS SQS로 발행한다. 실시간 조회와 어드민 재수집 요청은 템플릿을 사용하지 않고 출발상품 상세를 직접 조회한다.

출발일별 판매 정보는 출발일마다의 판매 상태와 가격을 모은 데이터다. 상품 서비스는 완료 이벤트를 수신해 판매 상품을 갱신하고, 좌석과 가격은 API 서비스를 호출해 모두투어의 현재 값으로 확인한다.

판매 종료 판정

동기화 배치는 모두투어 목록에 있는 상품만 저장된 상품과 비교한다. 모두투어가 목록에서 제외한 상품은 비교 대상에 포함되지 않으므로 판매 상태로 남는다.

판매 종료 배치는 동기화 배치와 별도로 매일 실행해 모두투어 목록과 저장된 상품을 대조하고, 저장된 상품에만 있는 상품을 판매 종료한다. 대조 대상은 판매 종료되지 않은 상품으로 제한하므로 이미 종료한 상품에 완료 이벤트를 다시 발행하지 않는다.

동기화 배치 안에서 함께 판정하는 구성과 비교하면 모두투어 목록을 한 번 더 읽는다. 대신 판매 종료 결과를 별도로 통지하고 판매 종료만 다시 실행한다.

판매 종료는 실행 주기인 하루 단위로 반영된다. 모두투어 목록이 매일 생성되므로 더 자주 실행해도 목록이 갱신되기 전의 결과는 같다.

실패 격리 단위

상품 하나의 판매 종료는 기초상품과 출발상품과 출발일별 판매 정보를 차례로 갱신하고 완료 이벤트를 발행하는 작업이다. 여러 상품을 일정 단위로 처리하던 구조에서는 1건의 실패가 같은 단위 전체의 실패로 기록되었고 해당 단위의 완료 이벤트도 발행되지 않았다.

판매 종료 배치는 상품을 1건씩 처리하고 실패한 상품을 기록한 뒤 다음 상품을 계속 처리한다. 결과 통지에 처리 건수와 실패 상품이 함께 포함되므로 실패 범위가 상품 단위로 확인된다.

상품마다 저장 호출이 나뉘므로 일정 단위로 처리할 때보다 저장 호출 수는 늘어난다. 처리 대상은 목록에서 제외된 상품으로 한정되므로 이 증가는 전체 상품 수에 비례하지 않는다.

수집 요청 락

API 서비스는 좌석과 가격을 조회할 때마다 모두투어의 현재 값을 저장된 값과 비교하고, 값이 다르면 수집을 요청한다. 저장된 값이 갱신되기 전까지 같은 차이가 계속 발견되므로, 기초상품 단위 Redis 락을 획득한 요청만 수집 요청을 발행한다.

락은 수집 서비스가 처리를 마칠 때까지 유지되어 수집 중의 중복 요청을 차단한다. 수집 처리가 오류로 종료되면 락은 만료 시간에 해제되므로 이후의 조회에서 수집 요청이 다시 발행된다.

이전 구조에서는 획득 키와 해제 키가 달라 해제 호출이 동작하지 않았고 락은 항상 만료 시간까지 유지되었다. 키 저장과 만료 설정도 별도 명령이어서 두 명령 사이에 프로세스가 중단되면 만료 없는 락이 남을 수 있었다.

현재 구조는 키 생성을 락 관리 클래스 하나로 통합하고 저장과 만료 설정을 하나의 명령으로 처리한다.

락이 기초상품 단위이므로 수집 중에는 같은 기초상품의 다른 출발일에서 발견한 차이도 수집 요청으로 이어지지 않는다. 이 차이는 저장된 값이 갱신될 때까지 남으므로 락이 해제된 뒤의 조회에서 다시 발견된다.

맡은 범위

다른 개발자가 주로 개발한 서비스에 2024년 10월부터 2025년 9월까지 참여해 기능 수정과 운영 개선과 PR 리뷰를 담당했다.

다음 항목을 직접 개발했다.

  • 판매 종료 배치를 작성하고 대조 대상을 판매 종료되지 않은 상품으로 제한했다.
  • 판매 종료 배치의 처리 단위를 상품 1건으로 변경했다.
  • 판매 종료 배치가 출발상품 종료 대상을 잘못 조회하던 버그를 수정했다.
  • 수집 요청 락의 키 불일치를 수정하고 저장과 만료 설정을 하나의 명령으로 통합했다.
  • 수집 요청 락을 수집 완료까지 유지하는 구조로 변경했다.
  • 출발상품 코드가 없는 수집 요청이 반복 처리되던 현상을 수정했다.

다음 영역은 다른 개발자가 개발했다.

  • 변경 감지와 항공편별 템플릿 수집
  • 실행 단위 분리와 실시간 조회
  • 수집 요청 락의 최초 구현
  • 상품 코드 체계 변경에 따른 판매 종료 대조 수정
