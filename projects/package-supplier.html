공급사 연동 서비스란

공급사 연동 서비스는 외부 여행사인 모두투어의 패키지 상품을 자사 판매 채널에서 함께 판매하도록 연결한다. 모두투어가 상품 변경을 통지하지 않으므로 서비스가 상품을 읽어 변경을 판정하고 결과를 상품 서비스에 전달한다.

모두투어 상품은 기초상품과 출발상품으로 구성된다. 기초상품은 여행 상품 하나이고, 출발상품은 기초상품을 출발일과 항공편별로 나눈 판매 단위다.

상품 서비스는 출발일의 좌석과 가격을 확인할 때 실시간 조회 서비스를 호출하고, 실시간 조회 서비스는 모두투어의 현재 값을 조회한다.

구성

완료 이벤트는 수집이나 판매 종료가 끝났음을 상품 서비스에 알리는 메시지다.

목록에서 제외된 상품

동기화 배치는 목록에 있는 상품만 비교하므로 모두투어가 목록에서 제외한 상품은 판매 상태로 남는다. 판매 종료 배치가 이 상품을 찾아 판매를 종료한다.

판매 종료를 동기화 배치와 분리하면 목록을 한 번 더 읽지만, 판매 종료 결과를 별도로 통지하고 판매 종료만 다시 실행할 수 있다.

실패 범위

이전 구조는 기초상품을 일정 단위로 묶어 처리해 1건의 실패가 같은 단위 전체의 실패로 기록되었다. 현재 구조는 1건씩 처리해 실패 범위가 해당 상품으로 한정된다.

저장 호출은 상품마다 나뉘어 늘어나지만, 처리 대상이 목록에서 제외된 상품이므로 전체 상품 수에 비례하지 않는다.

중복 수집 요청

실시간 조회 서비스는 조회마다 현재 값을 저장된 값과 비교하므로 저장된 값이 갱신되기 전까지 같은 차이가 계속 발견된다. 기초상품 단위의 Redis 락은 이 차이로 수집 요청이 반복 발행되는 일을 차단한다.

출발상품 단위 락과 비교하면 수집 요청이 줄어드는 대신, 수집 중 다른 출발일에서 발견한 차이의 갱신은 락 해제 뒤의 조회로 미뤄진다.

맡은 범위

다른 개발자가 주로 개발한 서비스에 참여해 기능 수정과 PR 리뷰를 담당했다. 다음 항목을 직접 개발했다.

  • 판매 종료 배치를 작성했다.
  • 판매 종료 배치의 처리 단위를 기초상품 1건으로 변경했다.
  • 수집 요청 락을 수정했다.

다음 영역은 다른 개발자가 개발했다.

  • 동기화 배치와 수집 서비스
  • 실시간 조회 서비스
  • 상품 코드 체계 변경에 따른 판매 종료 대조 수정
