상품 서비스란

상품 서비스는 공급 시스템별 여행 상품을 일정으로 묶어 패키지 여행 상품을 구성하고 출발일별 판매 상태를 관리한다. 좌석과 객실의 재고는 서비스 밖의 공급 시스템이 관리하므로 공급 시스템의 변경을 판매 상태에 반영하는 방식이 설계를 좌우한다.

구패키지 시스템에서는 담당자가 예약마다 금액과 일정을 직접 처리해 예약이 늘면 인력도 함께 늘어났다. 이를 대체하는 신규 패키지 시스템에서 상품 서비스는 상품 약 2만 개의 판매 상태 판단을 자동화한다.

구성

상품 서비스는 공급 시스템의 상품을 아이템으로 저장하고 아이템을 조합해 예약 단위와 고객 화면 단위를 구성한다.

완제품은 모두투어가 일정과 가격을 하나로 제공하는 상품이다.

같은 호텔과 항공을 여러 상품이 사용하므로 공급 단위와 예약 단위를 분리한다. 따라서 아이템 하나가 변경되면 그 아이템을 사용하는 아이템 그룹을 모두 다시 계산해야 한다.

재고 이벤트 처리

공급 시스템의 재고 이벤트는 변경 신호로만 사용하고 값은 공급 시스템에서 다시 조회한다. 호텔, 투어 이벤트마다 재고 조회가 1회 추가되는 대신 이벤트 값을 그대로 저장하던 이전 구현의 아래 한계가 사라진다.

아이템은 수량 대신 재고 유무만 저장하므로 수량이 0이 되거나 0에서 증가할 때만 아이템 그룹을 다시 계산한다. 판매 상태를 읽을 때마다 계산하면 출발일 수만큼 공급 시스템을 호출해야 하므로 변경 시점에 계산해 저장한다.

재고 선점

수기 예약은 담당자가 어드민 서비스에서 등록한 뒤 고객이 결제 기한 안에 결제하는 예약이므로 결제 전까지 재고를 확보하지 않으면 다른 예약이 같은 재고를 소진한다. 2026년 2월부터 신규 수기 예약의 선점은 공급 시스템 요청으로 대체되었고, 별도 문서에 선점을 기록하는 아래 방식은 이전 수기 예약의 처리 경로로 남아 있다.

재고 조회가 유효한 선점을 차감해 잔여 수량을 응답하므로 만료일이 지난 선점은 해제 작업 없이 차감에서 제외된다.

가격 달력 동시 계산

가격 달력은 출발일별 최저가와 판매 상태의 요약이고 캐시가 없는 상품은 상품별로 한 요청만 계산한다. 동시에 도착한 요청마다 출발일 전체를 계산하면 같은 계산이 중복되기 때문이다.

처리 중 표시는 Redis에 키가 없을 때만 저장되는 값이고 만료 시간이 있어 계산이 중단되어도 자동으로 해제된다.

맡은 범위

여러 개발자가 스프린트 단위로 작업을 나누어 개발하고 PR 리뷰로 함께 개선했다. 다음 항목을 직접 개발했다.

  • 공급 시스템 재조회 방식의 재고 동기화와 재고 유무 저장을 개발해 이벤트 값 저장 방식을 대체했다.
  • 판매 상태 계산을 재고 동기화와 연결하도록 다시 작성했다.
  • 재고 선점의 저장과 차감을 개발하고 예약 서비스의 수기 예약에 연결했다.
  • 가격 달력 캐시의 처리 중 표시와 호출별 대기 방식을 개발했다.

다음 영역은 다른 개발자가 개발했다.

  • 아이템과 아이템 그룹의 초기 구조
  • 실패 이벤트 보관과 항공 재고 이벤트의 지연 집계 큐
  • 2026년 2월의 수기 예약 선점 대체
