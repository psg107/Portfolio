법인단체 패키지 관리 서비스란

법인단체 패키지 관리 서비스는 기업과 단체가 의뢰한 맞춤 여행을 담당자가 직접 등록하고 관리하는 업무 시스템이다. 고객사마다 일정과 구성 항목이 다르고 출발 뒤에도 비용이 추가되어 금액이 변경되므로, 미리 구성한 상품을 자동 판매하는 신규 패키지 시스템과 별도로 개발되었다.

단체 여행 1건은 행사로 등록되고, 담당자는 출발일이 다른 출발그룹마다 업무를 처리한다.

구성

관리 서비스는 업무 기록을 자체 MySQL에 저장하고, 보험 가입이나 입금 확인 같은 일은 외부 시스템을 호출해 처리한다.

외부 호출과 실패 범위

외부 시스템에서 완료된 처리는 DB 트랜잭션으로 되돌릴 수 없다. 외부 호출의 단위가 다른 기능은 실패 범위도 다르다.

기능외부 호출실패 범위
명단 일괄 등록없음파일 전체
보험 가입여행자마다해당 여행자
입금 매칭요청마다 한 번해당 출발그룹

명단 일괄 등록은 저장 전에 행을 순서대로 검증하고 오류가 없는 파일만 한 트랜잭션에서 저장하므로 담당자가 저장된 행을 구분할 필요가 없다. 검증은 첫 오류 행의 번호와 사유를 반환하고 중단하므로 오류가 여러 건이면 담당자가 업로드를 반복한다.

보험 가입 실패 격리

여행자 전체를 한 트랜잭션으로 묶으면 1명의 실패로 다른 여행자의 저장 결과가 되돌아가 보험사에는 가입되어 있는데 기록이 없는 상태가 발생한다. 여행자마다 보험사 API를 호출하면 실패가 해당 여행자의 기록에만 남는다.

호출 전에 상태를 커밋하므로 서버가 호출 도중 중단되어도 진행 중 기록이 저장소에 유지된다. 재호출은 자동으로 실행되지 않아 담당자의 요청이 한 번 더 필요하지만 재호출 시점과 대상을 담당자가 결정한다.

입금 매칭의 부분 성공

고객사의 계좌 입금 1건을 여러 출발그룹에 금액별로 배분해 결제로 연결하는 일이 입금 매칭이고, 정산 시스템은 배분 목록을 한 번에 받아 배분별 성공 여부를 반환한다. 일부 배분만 실패할 때 전체를 실패로 처리하면 정산 시스템의 매칭과 관리 서비스의 결제 기록이 어긋나므로, 관리 서비스는 성공한 배분만으로 결제 기록을 생성한다.

담당자는 매칭 내역 화면에서 출발그룹별 성공과 실패를 확인한다.

번호 발급과 행 잠금

행사번호와 출발그룹번호는 날짜별로 구분되고, 보험 일련번호는 여행자별 병렬 요청에서 같은 값이 중복되면 안 된다. 관리 서비스는 이 번호들을 MySQL 행에 저장하고 행을 잠근 뒤 값을 증가시킨다.

방식이 서비스에 적용할 때
자동 증가 컬럼날짜별 번호 표현 불가
Redis 증가 연산번호 발급만을 위해 Redis 추가
DB 행 잠금기존 MySQL로 동작

행사번호와 출발그룹번호는 등록 트랜잭션에 참여하므로 등록이 실패하면 번호도 되돌아가 빈 번호가 생기지 않는다. 보험 일련번호는 별도로 커밋해 잠금을 먼저 해제하므로 보험사 호출이 실패하면 빈 값이 남지만 다른 여행자의 번호 발급이 보험사 응답을 기다리지 않는다.
