AI 챗봇 문서 학습 서비스란

업무 문서의 의미를 숫자 벡터로 변환(임베딩)해 저장하고, 질문과 벡터가 가까운 문서를 근거로 LLM이 답하는 챗봇 시제품이다. 패키지 여행 개발팀에는 상품 등록 방법 같은 사업부 문의가 반복되고 관련 문서는 여러 도구에 흩어져 있다.

답변 품질이 기대에 미치지 못해 실제 문의 응답에는 사용하지 않는다.

구성

서비스는 문서를 적재하는 흐름과 질문에 답하는 흐름으로 구성되고, 적재는 사람이 단계마다 API를 호출해 실행한다.

단계별 저장

Jira와 Confluence API는 대량 수집 중 요청 제한 오류를 반환한다. 같은 문서를 다시 수집할 때는 Redis에 캐시한 응답을 사용하고, 전처리 규칙이나 임베딩 구현을 수정할 때는 단계마다 저장한 문서에서 다시 시작하므로 어느 쪽도 외부 API를 다시 호출하지 않는다.

문서와 질문의 벡터는 같은 구현으로 생성되어 항상 같은 모델을 사용하고, 구현을 교체하면 주입 대상을 변경한 뒤 문서를 다시 임베딩한다. 변경 감지가 없어 재실행은 저장된 문서 전체를 다시 처리한다.

실사용 보류와 에이전트 전환

수집부터 질문 응답까지 모두 동작하지만 실제 문의 응답에는 사용하지 않는다. 품질 수치와 질문별 성공 기록이 없어 다음 구분은 개발 후 작성한 회고의 추정이다.

다음 요인이 답변 품질에 미친 영향은 확인되지 않았다.

  • 전처리가 단어 사이 공백까지 제거한다.
  • 임베딩 모델이 영어 문서용이다.
  • 검색 결과 재순위화와 키워드 병행 검색이 적용되어 있지 않다.

문서에 값이 없는 질문은 검색을 개선해도 답할 수 없다. 후속 설계는 LLM이 도구를 호출해 현재 데이터와 코드를 여러 번 조회하는 에이전트 구조로 전환하고, 구현은 사내 문의 자동응답 에이전트에 있다.

맡은 범위

서비스 전체를 단독으로 개발했다. 체감 답변 품질 미달을 근거로 실사용을 보류하고 에이전트 방식의 후속 계획을 작성했다.
