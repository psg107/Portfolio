AI 챗봇 문서 학습 서비스란

패키지 여행 시스템 개발팀에는 사업부의 같은 문의가 반복되고, 신규 입사자는 여러 도구에 흩어진 문서에서 도메인 지식을 찾아야 한다.

문서 학습 서비스는 Jira와 Confluence와 PDF 문서를 수집해 검색용 벡터로 저장하고, 질문과 가까운 문서를 근거로 LLM이 답변을 생성한다. 이 방식을 검색 증강 생성(RAG)이라 한다.

답변 품질이 기대에 미치지 못해 실제 문의 응답에는 사용하지 않은 시제품이다.

구성

문서 학습 서비스는 문서를 적재하는 흐름과 질문에 답하는 흐름으로 동작한다. 적재는 수집과 전처리와 임베딩 API를 사람이 순서대로 호출하고, 단계별 결과는 MongoDB에 저장한다.

LLM에는 근거 문서가 없으면 모른다고 답하도록 프롬프트로 지시하고, 출처 목록을 JSON으로 함께 반환받는다.

Jira 이슈와 Confluence 페이지는 문서 1건에 벡터 1개를 생성하고, PDF는 페이지 텍스트를 1500자 이하 조각(청크)으로 나누어 조각마다 벡터를 생성한다.

단계별 저장

개발 기간에 전처리 규칙은 2회 수정되었고 임베딩 구현은 JVM 내장 모델에서 Python 서버 모델로 교체되었다. 원본 문서와 정제 문서와 벡터 문서는 컬렉션 3개에 나뉘어 있고 단계마다 별도 API로 실행한다.

수집부터 임베딩까지 한 번에 실행하는 구조와 비교하면 전처리 규칙을 수정해도 외부 API를 다시 호출하지 않는다. 임베딩 모델을 교체하면 저장된 정제 문서에서 다시 시작하므로 전처리도 반복하지 않는다.

단계 실행은 사람이 API를 순서대로 호출해야 하고, 변경 감지가 없어 재실행은 저장된 문서 전체를 다시 처리한다. 실사용 전 시제품에는 정기 실행 요구가 없어 수동 실행으로 규칙 수정을 반복한다.

외부 API 응답 캐시

Jira와 Confluence API는 대량 수집 중 요청 제한 오류를 반환한다. 수집 서비스는 응답을 Redis에 7일 동안 캐시해 같은 문서를 다시 수집할 때 외부 API를 호출하지 않는다.

재시도는 Confluence 호출에만 적용한다.

캐시가 유효한 7일 동안은 원본 문서의 변경이 수집에 반영되지 않는다. 유지 기간은 소스별 설정값이어서 문서 최신성 요구가 높아지면 설정만 수정한다.

임베딩 서버 분리

임베딩은 문장을 벡터로 변환해 의미가 가까운 문서를 찾게 하는 단계다. JVM 내장 모델은 개발팀의 주 언어인 Kotlin 애플리케이션 안에서 실행되지만 품질이 부족하다는 개발 중 판단에 따라 문서 임베딩과 질문 임베딩은 별도 서버의 BGE 모델을 사용한다.

기준JVM 내장 모델Python 서버 모델
모델AllMiniLM-L6-v2BGE base en v1.5
실행 위치애플리케이션 프로세스별도 FastAPI 프로세스
추가 실행 부담없음서버 1개를 함께 실행

두 모델의 품질 차이를 측정한 수치는 없다. BGE 모델은 영어 문서용이고 적재 대상 문서는 주로 한국어여서 모델 선택이 답변 품질에 미친 영향도 확인되지 않았다.

두 구현은 같은 임베딩 인터페이스를 따르므로 주입 대상 이름만 수정해 교체한다. 문서 임베딩과 질문 임베딩이 같은 구현을 주입받아 두 벡터는 같은 모델로 생성된다.

별도 서버를 함께 실행하므로 임베딩 서버가 실행 중이 아니면 문서 임베딩과 질문 응답이 모두 실패한다. 임베딩 서버는 애플리케이션과 같은 장비에서 실행되고 실사용 요청이 없어 이 의존은 시제품 범위에서 감수한다.

실사용 보류와 에이전트 전환

파이프라인과 질의 API는 동작하지만 답변 품질이 기대에 미치지 못해 실제 문의 응답에는 사용하지 않는다. 품질 수치와 질문별 성공 기록이 없어 원인을 특정하지 못하고, 개발 회고는 문서 구조와 질문 유형에서 원인을 추정한다.

  • PDF 청크처럼 문서를 조각으로 나누면 문맥이 분리되어 질문에 직접 답하지 못하는 조각이 검색된다.
  • 문서에는 기능의 설명만 있어 코드를 확인해야 답할 수 있는 질문에 답하지 못한다.
  • 특정 상품의 현재 상태를 묻는 질문은 문서에 상태의 종류 설명만 있어 답할 수 없다.
  • 특정 상태가 된 이유를 묻는 질문은 규칙과 실제 데이터가 함께 필요해 검색 1회로 근거를 모으지 못한다.

전처리가 단어 사이 공백까지 제거하는 결함이 남아 있어 품질 미달을 구조의 한계로만 단정할 수 없다. 재순위화와 하이브리드 검색은 적용되어 있지 않아 두 방법으로 RAG 품질이 개선되는지도 확인되지 않았다.

남은 경로는 RAG 검색을 개선하는 방법과 에이전트가 도구로 현재 데이터와 코드를 조회하는 구조로 전환하는 방법이다. 문서에 값이 없는 질문은 검색을 개선해도 답할 수 없으므로 에이전트 구조로 전환한다.

질문별 성공 기록이 없으므로 이 구분은 추정이다.

후속 구현은 사내 문의 자동응답 에이전트 프로젝트에 있다.

맡은 범위

서비스 전체를 단독으로 설계하고 개발했다.

  • 수집과 전처리와 임베딩을 단계별 API로 분리하고 결과를 컬렉션 3개에 저장하는 구조를 작성했다.
  • Jira와 Confluence 응답 캐시와 Confluence 요청 제한 재시도를 작성했다.
  • BGE 모델 임베딩 서버를 FastAPI로 작성했다.
  • 질문 벡터 검색과 답변 생성 API를 작성했다.
  • 답변 품질 미달을 근거로 실사용을 보류하고 에이전트 방식의 후속 계획을 작성했다.
