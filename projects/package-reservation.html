예약 서비스란

예약 서비스는 결제가 끝난 주문을 예약으로 저장하고 공급 시스템의 승인 결과를 모아 예약 상태를 관리하며 취소와 환불도 처리한다. 공급 시스템은 좌석과 객실을 실제로 확보하는 별도 시스템이다.

패키지 여행 한 건은 이 시스템들의 상품을 묶어 판매하므로 결제가 끝나도 각 시스템이 승인해야 예약이 확정된다. 그래서 서비스는 거부와 오류의 결과를 기록하고 담당자는 그 기록을 보고 후속 처리를 진행한다.

구성

예약 서비스는 고객 화면과 담당자의 요청을 처리하고 상품과 재고는 별도의 상품 서비스를 호출해 사용한다.

반려와 실패

반려는 예약 서비스가 공급 시스템의 거부로 분류한 결과이고 실패는 그 밖의 오류다. 반려는 전체 취소로 이어지고, 실패는 담당자가 재요청하므로 사람의 개입이 필요한 대신 같은 예약을 자동으로 반복 요청하지 않는다.

이 구분은 호텔, 투어 연동에 이미 있었지만 후속 처리는 공급 시스템마다 달랐다. 현재 구조는 어느 경로의 거부든 반려 큐에 발행하고, 전체 취소가 실패하면 메시지가 큐에 남아 다시 전달된다.

수기 예약

홈쇼핑 상품 예약은 담당자가 어드민에서 수기로 등록한 뒤 고객이 알림톡 링크에서 결제 기한 안에 결제한다. 등록과 결제 사이에 시간이 있으므로 그동안 등록 내용과 재고를 유지해야 한다.

일반 예약의 가예약은 결제 직전에 생성하는 임시 예약이라 수정과 만료를 표현하지 못한다. 그래서 수기 예약은 별도 문서로 저장하고 고객이 결제를 시작할 때 가예약으로 변환해 이후 결제와 접수는 일반 예약과 같은 경로를 사용한다.

2026년 2월부터 신규 수기 예약의 재고 확보는 공급 시스템 선점 요청으로 대체되었고, 도해의 상품 서비스 선점은 그 이전에 등록한 수기 예약의 경로다.

출발일 예약 분석

담당자가 상품과 출발일을 지정하면 예약 서비스가 예약별 금액과 합계를 계산하고 금액 조정이나 여행자 추가의 결과도 미리 계산한다. 여행자 수에 따라 적용 금액이 달라지는 항목이 있어 한 예약의 변경도 출발일 전체의 합계에 영향을 미친다.

가정 계산은 예약 문서를 다시 조회하지 않고 저장된 분석을 기준으로 실행하므로 여러 가정을 같은 기준에서 비교한다. 저장된 결과도 변경하지 않으므로 입력을 달리해 반복해도 결과가 누적되지 않는다.

맡은 범위

여러 개발자가 스프린트 단위로 작업을 나누어 개발하고 PR 리뷰로 함께 개선했다. 다음 항목을 직접 개발했다.

  • 반려와 실패의 후속 처리를 전용 큐로 분리하고 항공 시스템의 거부 응답을 반려 경로로 연결했다.
  • 수기 예약의 문서 모델과 등록부터 결제 연결까지의 처리를 개발했다.
  • 수기 예약의 재고 선점 호출과 상품 서비스의 선점 모델을 개발했다.
  • 출발일 예약 분석과 가정 계산을 개발했다.

다음 영역은 다른 개발자가 개발했다.

  • 반려와 실패의 구분 분기
  • 위약금 없는 전체 취소 요청과 재요청 API
  • 결제 승인 통보 처리
  • 접수 경로의 분리(담당 기간 이후 변경)
  • Kinesis 상태 이벤트 수신
  • 보험사 연동 본체와 공급 시스템 재고 선점
