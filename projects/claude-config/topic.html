토픽

토픽이란

Claude Code 세션이 끝나거나 대화가 길어져 Claude Code가 앞부분을 요약으로 대체하면, 다음 세션은 앞서 내린 결정과 진행 상황을 알지 못한다.

토픽은 업무마다 하나씩 생성하는 노트 폴더이고, 업무의 결정과 진행 상황을 폴더 맨 위의 상태 문서(CLAUDE.md)에 기록한다. Claude Code는 세션을 시작한 폴더의 CLAUDE.md를 자동으로 읽으므로, 토픽 폴더에서 시작한 세션은 상태 문서부터 읽고 같은 업무를 이어 간다.

구성

토픽 폴더 바로 아래에는 상태 문서와 정해진 하위 폴더만 둔다.

상태 문서는 이름과 순서가 정해진 섹션 10개로 나뉜다. History와 Sessions에는 항목을 아래에 추가만 하고, 나머지 섹션은 다음 세션이 현재 상태만 읽도록 갱신할 때마다 다시 작성한다.

갱신 훅

에이전트가 작업 중에 상태 문서 갱신을 누락하면 다음 세션은 갱신되지 않은 내용을 읽는다. 그래서 갱신 훅이 세션 하나 안의 정해진 시점마다 에이전트에게 상태 문서 갱신을 요구한다.

요약 직전에 저장한 상태 문서를 요약 직후에 Claude Code가 다시 읽는다.

형식 규칙

섹션 설명

섹션마다 기록하는 내용은 다음과 같다.

섹션기록하는 것
Summary업무 목적, 접근 방식, 현재 위치의 요약
Now현재 위치, 진행 중인 작업, 다음 작업, 재개 방법
Directives이후 세션이 지킬 지시와 금지
Context업무 동안 바뀌지 않는 배경
Decisions현재 유효한 결정과 근거
Failed Approaches기각한 접근과 기각 사유
Open Items시작하지 않은 작업과 미결 질문
Workspace토픽 안 파일의 경로 목록
History날짜별 사건
Sessions세션 대화 기록 파일의 경로

지침 규칙

섹션마다 기록할 내용만 정해 두면 뒤집힌 결정이나 지난 경과가 상태 문서에 계속 남는다. 그래서 토픽 스킬의 지침 문서는 섹션마다 기록하지 않을 내용과 갱신 방법을 아래 규칙으로 정하고, 에이전트는 상태 문서를 갱신할 때 아래 규칙을 따른다.

섹션규칙
Summary
  • 날짜, 사건 서술, 진행 수치 상세, 파일 위치 안내는 적지 않는다.
  • 항목은 3개, 많아도 4개로 둔다.
  • 첫 항목에 무엇을 왜 하는지 적는다.
  • 둘째 항목에 접근과 최상위 제약을 적는다.
  • 셋째 항목에 현재 위치를 한 줄로 적는다.
  • 다른 섹션에 있는 내용만 요약한다.
Now
  • 시간순 사건과 시작하지 않은 작업은 적지 않는다.
  • 갱신할 때마다 전체를 다시 작성한다.
  • 직전 세션의 상태만 남긴다.
  • 완료 토픽은 '- 없음'만 둔다.
Directives
  • 상태 서술과 배경 설명은 적지 않는다.
  • 명령형 문장으로 다시 작성해도 뜻이 같은 지시만 적는다.
Context
  • 결정, 수행한 변경, 현재 설정 값, 진행 단계는 적지 않는다.
  • 다음 세션에서도 참인 문장만 적는다.
Decisions
  • 뒤집힌 결정과 미결 사항은 적지 않는다.
  • 지금 그대로 따라도 되는 결정만 남긴다.
  • 다시 시도하지 말아야 할 접근은 기각 사유와 함께 Failed Approaches로 이동한다.
  • 단순한 방침 변경은 History에만 기록한다.
Failed Approaches
  • 단순 버그 수정 이력은 적지 않는다.
  • 모르면 반복할 수 있는 접근만 기록한다.
Open Items
  • 진행 중 작업의 경과와 끝난 항목은 적지 않는다.
  • 진행 경과는 Now로 이동한다.
Workspace
  • 경로가 있어야 뜻이 통하는 항목만 둔다.
History
  • 항목은 아래에 추가만 하고 기존 항목은 수정하지 않는다.
  • 지금 상태는 History 없이 다른 섹션만으로 알 수 있게 한다.
Sessions
  • 사용자가 직접 작성한 항목은 두지 않는다.

구조 검사기 규칙

지침은 에이전트가 읽고 따르는 문장이므로, 에이전트가 규칙을 누락하면 토픽마다 형식이 달라진다. 그래서 기계적으로 판단할 수 있는 규칙은 구조 검사기(topic-lint.py)가 강제한다.

구조 검사기는 섹션 규칙과 함께 폴더 이름과 머리 정보 같은 폴더 형식도 검사한다.

갱신 훅은 파일을 작성할 때마다 구조 검사기를 실행한다.

  • 오류는 규칙 위반이므로 에이전트가 응답을 마치기 전에 수정한다.
  • 경고는 상태 문서가 길어지거나 항목이 섹션 기준에서 벗어나는 징후이므로, 에이전트가 반영하거나 반영하지 않는 사유를 기록한다.
대상조건결과
폴더
  • 폴더 이름이 YYMMDD-HHMM-제목 형식이 아니다.
  • 폴더 바로 아래에 허용하지 않는 파일이나 폴더가 있다.
  • 빈 폴더나 개발 도구 폴더가 있다.
오류
업무노트 폴더
  • 토픽을 모아 둔 폴더에 토픽이 아닌 폴더가 있다.
오류
하위 폴더의 파일
  • work/ 문서 파일명이 NN-제목.md 형식이 아니다.
  • work/ 문서의 첫 줄이 h1 제목이 아니다.
  • tools/에 md 노트가 있다.
  • sources/에 출처 목록이 없거나 실제 파일과 일치하지 않는다.
오류
머리 정보
  • 필수 필드(title, status, created, updated, ticket, tags)가 없다.
  • 허용하지 않는 필드가 있다.
  • 태그가 비었거나 태그 목록(tags.txt)에 없다.
  • 상태 값이 진행중이나 완료가 아니다.
  • 날짜 형식이 틀렸다.
  • 티켓 값이 Jira 키 형식이 아니다.
  • 제목이나 생성일이 폴더 이름과 다르다.
  • 다른 토픽으로 가는 연관 링크의 형식이 틀렸거나 대상이 없다.
오류
섹션 공통
  • 섹션 순서가 정해진 순서와 다르다.
  • h3가 있다.
  • 목록이 아닌 줄이 있다.
  • 2단보다 깊은 항목이 있다.
  • 빈 섹션이 있다.
  • 코드 블록이 있다.
  • 백틱 밖에 # 낱말이 있다(옵시디언이 태그로 인식한다).
  • 적은 경로가 실제로 없다.
오류
섹션 공통
  • History와 Sessions를 제외한 본문이 진행중 4000자, 완료 3000자를 초과한다.
  • 한 항목이 300자를 초과한다.
  • 항목이 '하고'나 '하며' 같은 연결 어미로 끝난다.
경고
Summary
  • 항목이 4개를 초과한다.
경고
Now
  • 완료 토픽의 Now에 내용이 있다.
경고
Directives
  • 항목이 지시가 아닌 상태 서술로 끝난다.
경고
History
  • 형식이나 날짜 순서가 틀렸다.
오류
History
  • 최신 날짜가 머리 정보의 수정일보다 늦다.
경고
Sessions
  • 형식이나 순서가 틀렸다.
오류
설계 문서와 검증 케이스
  • 설계 문서 검사기나 케이스 검사기가 오류를 검출했다.
