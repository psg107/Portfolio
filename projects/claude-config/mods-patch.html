모드와 cc-patch

모드와 cc-patch란

이 환경은 Claude Code를 터미널 화면에서 사용한다. 기본 화면은 남은 작업 목록과 사용자 조치가 필요해 멈춘 보고를 일반 코드와 같은 형식으로 표시하므로, 긴 응답에서 필요한 부분을 빠르게 찾기 어렵다.

Claude Code의 플러그인 기능으로는 응답 표시 방식처럼 Claude Code가 허용한 동작만 변경할 수 있다. 입력 상자의 색 표시나 Ctrl+B 잘라내기 같은 입력 동작은 플러그인으로 변경할 수 없다.

터미널 화면을 작업 방식에 맞게 변경하는 장치는 두 가지다.

  • 모드(mod)는 Claude Code가 응답을 터미널에 표시하는 방식을 변경하는 플러그인이다. 응답 블록 표시 모드(code-block-box)는 응답 원문의 코드 블록을 테두리 상자와 색 라벨로 표시한다.
  • cc-patch는 설치된 Claude Code 실행 파일을 직접 수정해, 플러그인으로 변경할 수 없는 동작을 변경하는 스킬이다. cc-patch 스킬이 관리하는 패치 13개도 cc-patch로 부른다.

구성

모드는 Claude Code가 응답을 그리기 직전에 실행되고, cc-patch는 Claude Code 실행 파일을 미리 수정한다. Claude Code 실행 파일은 JS 모듈 여러 개를 하나로 합친 파일이므로, cc-patch는 모듈을 추출해 수정한 뒤 다시 조립한다.

블록별 그리기

모드가 응답을 부분별로 구분해 그리려면 응답 안에 구분 표시가 있어야 한다.

응답 형식(output style)은 에이전트가 남은 작업 목록을 checklist 블록에, 멈춘 보고를 blocked 블록에 작성하게 한다. 모드는 코드 블록 시작 줄에 적힌 블록 이름에 따라 그리는 방식을 정한다.

아래 응답은 Claude Code가 기본 방식으로 그린다.

  • 블록이 없는 응답
  • 코드 블록 끝 표시가 아직 출력되지 않은 생성 중인 응답
  • mermaid 블록이 있는 응답

패치 목록

cc-patch가 관리하는 패치는 13개이고, 표의 행 순서는 apply.py가 패치를 적용하는 순서다.

패치하는 일
highlighter입력 상자의 파일 경로와 환경 변수와 따옴표 문자열을 색으로 표시한다.
askuserquestion에이전트가 사용자에게 선택지를 제시해 질문하는 질문 도구의 질문 수와 선택지 수 상한을 4에서 10으로 확대한다.
paste-inline짧은 여러 행 붙여넣기를 원문 그대로 입력 상자에 표시한다.
askq-noescape질문 도구 설명에 한글을 이스케이프하지 말라는 지시를 추가해 질문 화면에 한글을 원래 글자로 표시한다.
self-inject스킬이 지정 파일에 기록한 명령(예: /compact)을 턴이 끝나면 현재 세션이 직접 실행하게 한다.
input-copyCtrl+B로 입력 내용을 클립보드에 복사하고 입력 상자를 비운다.
response-style응답의 인라인 코드 맨 앞에 표시한 완료와 경고 같은 상태 기호에 따라 색을 적용하고 제목 단계마다 색을 지정한다.
table-border-color마크다운 표의 배경과 테두리 색을 변경한다.
table-hscroll화면보다 넓은 표를 표 형식으로 유지하고 좌우로 스크롤하게 한다.
thinking-expand기본 화면이 출력 후 한 줄로 접는 사고 과정(모델이 응답 전에 출력하는 내용)을 항상 펼쳐 표시한다.
logo-color시작 로고 색을 초록으로 변경해 패치한 실행 파일임을 표시한다.
last-turn-bar마지막 턴의 모든 행 왼쪽에 빨간 막대를 그린다.
statusline-hover상태 줄 구간에 마우스를 올리면 설명 카드를 표시한다.

재적용 절차

Claude Code 업데이트는 패치한 실행 파일을 새 파일로 교체하므로 적용한 패치가 모두 제거된다. 그래서 이 환경은 Claude Code 자동 업데이트를 비활성화한다.

새 버전을 설치할 때는 Claude Code 대화창에 /cc-patch를 인자 없이 입력한다. 그러면 cc-patch 스킬이 아래 절차를 질문 없이 끝까지 진행한다.

패치 앵커는 패치가 코드를 삽입할 위치를 정규식으로 찾는 표식이다. 압축된 코드의 변수 이름은 버전마다 다르지만, 앵커는 코드 구조를 기준으로 위치를 찾으므로 새 버전에서도 대부분의 패치가 그대로 적용된다.

작성 규칙

잘못된 패치는 실행 파일을 시작하지 못하게 하거나, 적용 확인을 통과하고도 동작하지 않는다. 그래서 패치를 작성할 때는 아래 규칙을 따른다.

규칙이유
  • 패치마다 claude --version으로 실행 파일이 시작하는지 확인한다.
패치를 삽입하는 adhoc.mjs는 주입한 JS의 문법을 검사하지 않아서, 문법 오류가 있으면 실행 파일이 시작하지 못한다.
  • 원본 실행 파일 대신 사본에서 먼저 시험한다.
원본 실행 파일에 잘못된 패치를 적용하면 Claude Code를 실행할 수 없다.
  • import.meta가 없는 모듈에는 import.meta를 사용하는 코드를 주입하지 않는다.
import.meta를 사용하는 주입 코드는 버전 확인과 패치 표식 문자열 확인을 모두 통과해도, Ctrl+B를 누르면 프로세스를 종료시킨다.
  • 도구 설명 문구를 앵커로 삼는 패치는 모델에 보내는 문구에 주입되었는지 다시 확인한다.
askq-noescape처럼 앵커가 실행 파일에 남은 이전 문구와 일치하면, 적용된 것으로 보고되어도 모델에 보내는 새 문구에는 주입되지 않는다.
