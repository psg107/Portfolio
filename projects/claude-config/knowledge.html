지식 수집

지식 수집이란

다이나믹 패키지의 정책과 합의는 여러 사내 기록에 나뉘어 있다.

  • Confluence 페이지
  • Jira 이슈
  • Slack 스레드
  • GitHub 리뷰 댓글
  • 토픽 상태 문서

업무 질문에 답하려면 현재 사실을 한곳에서 조회하면서 사실마다 원본까지 거슬러 확인할 수 있어야 한다.

지식 수집(knowledge)은 사내 기록을 평일마다 수집해 정책과 합의를 개념별 노트로 정리하는 체계이고, 에이전트는 업무 질문에 답할 때 노트를 읽는다. 개념은 '도착지 검색 키워드 해석'처럼 다른 노트에서 링크할 만한 기능이나 정책 하나다.

언어 모델은 노트의 사실 항목마다 근거 문서를 가리키는 인용 표시를 기록한다. 노트는 언어 모델이 요약한 문서이므로 사용자가 검토하기 전에는 가설로 취급하고, 에이전트는 노트의 내용을 코드에서 다시 확인한다.

구성

수집에서 노트까지는 스크립트 단계와 언어 모델 단계로 나뉜다.

  • 수집 스크립트(ingest.py)가 출처별 변경분을 원본 사본으로 저장한다.
  • 정규화 스크립트(normalize.py)가 출처마다 다른 형식을 같은 머리 정보를 가진 마크다운 문서로 변환한다.
  • 배치 스크립트(batch.py)가 언어 모델로 노트를 작성한다.
  • 구조 검사 스크립트(lint.py)가 머리 정보와 인용 표시를 검사해, 가리키는 문서가 실제로 있는지 확인한다.

검사를 통과한 문서만 처리 완료로 기록하므로 실패한 문서는 다음 배치가 다시 처리한다.

평일 아침마다 업무일지를 작성하는 루틴이 배치 스크립트도 함께 실행한다.

노트의 인용 표시는 정규화 문서를 가리키고 정규화 문서는 원본 사본을 가리켜, 노트의 사실에서 원본까지 거슬러 확인할 수 있다.

수집 범위

출처마다 변경을 판단하는 방법이 달라, 수집 스크립트는 출처별로 수집 범위와 변경 판단 기준을 따로 정한다.

출처수집 범위변경 판단
Confluence팀 공간 등의 페이지 본문페이지 버전 비교
Jira팀 프로젝트의 이슈와 팀원이 담당한 이슈마지막 갱신 시각 이후 변경분
Slack지정 채널의 스레드와 답글마지막 답글 시각 비교
GitHub팀 저장소의 PR 본문과 리뷰마지막 갱신 시각 이후 변경분
토픽로컬에 있는 상태 문서(CLAUDE.md)원본 파일 해시 비교

형식 규칙

정규화 문서 형식

출처마다 원본 형식이 달라, 정규화 스크립트는 모든 출처의 문서를 같은 머리 정보와 출처별로 정해진 본문 섹션으로 변환한다. 정규화 문서는 스크립트만 생성하고, 사람과 언어 모델은 수정하지 않는다.

머리 정보기록하는 것

source_url원본 주소
raw 또는 origin원본 사본의 경로, 토픽처럼 로컬에 원본이 있으면 원본 파일의 경로
fetched origin_updated수집 시각과 원본 갱신 시각
content_hash원본 내용의 해시

  • Description
  • Comments
GitHub

  • 본문
  • 리뷰
  • 코멘트

  • 대화

토픽

노트 형식

노트 본문은 섹션 세 개로 나누고, 머리 정보에 인용한 문서와 버전을 기록한다.

위치기록하는 것
Summary개념의 현재 상태 요약
Facts인용 표시를 붙인 사실 항목
References인용한 정규화 문서 목록
머리 정보제목, 인용 문서 목록, 태그, 버전, 원본과 대조한 시각, 연관 토픽

지침 규칙

노트는 언어 모델이 작성하므로, 정해 두지 않으면 출처 없는 사실이나 지난 주장이 노트에 남는다. 그래서 지식 수집 폴더의 규칙 문서(CLAUDE.md)가 아래 규칙을 정하고, 배치 스크립트가 실행한 언어 모델은 노트를 작성할 때마다 규칙 문서를 먼저 읽고 따른다.

대상규칙
노트 단위
  • 다른 노트에서 링크할 독립 개념일 때만 새 노트를 만든다.
  • 그 밖에는 기존 노트를 갱신한다.
본문
  • 현재 사실만 서술하고 변천사는 적지 않는다.
  • 지금은 폐기되었지만 나중에 유효할 수 있는 주장은 별도 노트로 분리한다.
  • 목록 항목만 둔다.
인용
  • 정규화 문서만 인용하고 원본 사본이나 다른 노트는 인용하지 않는다.
  • Facts 항목마다 근거 문서를 가리키는 인용 표시를 기록한다.
  • 출처를 제시할 수 없는 사실은 작성하지 않는다.
충돌
  • 인용한 문서끼리 사실이 충돌하면 원본 갱신 시각이 늦은 쪽을 따른다.
  • 시각으로 판단할 수 없으면 양쪽을 근거와 함께 기록한다.
교정
  • 사용자는 폴더의 파일을 직접 수정하지 않고 틀린 사실을 에이전트에게 지적한다.
  • 에이전트는 교정 기록을 작성한 뒤 노트를 다시 작성한다.
  • 교정 기록은 충돌 규칙보다 우선한다.
버전
  • 본문이 변경될 때마다 버전을 1씩 올리고, 내용이 같으면 저장하지 않는다.
  • 검토는 특정 버전에 대한 판정이므로, 버전이 바뀌면 노트는 다시 가설로 인용된다.
태그와 연관 토픽
  • 태그는 태그 목록(tags.txt)에 있는 것만 사용하고, 새 태그는 후보 파일에 기록한다.
  • 연관 토픽은 티켓 키가 일치하는 것처럼 근거가 확실한 토픽만 연결한다.

구조 검사기 규칙

지침은 언어 모델이 읽고 따르는 문장이므로 규칙을 누락할 수 있다. 그래서 기계적으로 판단할 수 있는 규칙은 구조 검사 스크립트(lint.py)가 검사하고, 배치 스크립트는 위반이 하나라도 있으면 해당 배치의 문서를 처리 완료로 기록하지 않는다.

대상조건결과
폴더
  • 토픽 전용 날짜 접두가 붙은 파일이나 폴더가 있다.
  • 최상위에 정해진 폴더 외의 항목이 있다.
오류
원본 사본
  • 파일 이름이 출처별 이름 규칙과 다르다.
  • 수집 기록에 없거나 기록된 해시와 내용이 다르다.
오류
정규화 문서
  • 필수 머리 정보가 없다.
  • 가리키는 원본이 없거나 원본의 해시와 다르다.
오류
노트 머리 정보
  • 필수 필드가 없다.
  • 버전이 1 이상의 정수가 아니다.
  • 인용 문서가 정규화 문서에 없다.
  • 태그가 태그 목록에 없다.
  • 연관 토픽이 없다.
오류
노트 본문
  • 섹션이 Summary, Facts, References 순서의 세 개가 아니다.
  • Facts 항목에 인용 표시가 없다.
  • 인용 표시가 머리 정보의 인용 문서나 교정 기록에 없다.
오류
검토와 교정 기록
  • 기록을 읽을 수 없거나 값이 허용 범위 밖이다.
  • 폐기한 노트의 파일이 남아 있다.
오류

조회와 확인

노트는 검토 전에는 틀릴 수 있어, 조회 스킬(knowledge:query)은 노트를 인용할 때 검토 여부를 함께 표시하고 에이전트가 사실을 다시 확인하게 한다.

조회 스킬은 다음 순서로 노트를 조회한다.

  • 전체 노트의 제목 목록인 노트 목차에서 후보 노트를 선택한다.
  • 후보 노트의 본문을 읽는다. 현재 사실을 정리한 문서는 노트뿐이므로 정규화 문서는 조회하지 않는다.
  • 검토 기록을 확인해 노트를 검토됨이나 가설로 인용한다.

조회 스킬은 검토된 노트도 코드에서 다시 확인할 사실로 인용한다. 원본이 노트보다 나중에 변경되었으면 원본이 더 최신일 수 있다고 표시한다.

노트에 답이 없으면 조회 스킬은 토픽 기록을 조회하는 스킬 topic:query나 Jira와 Slack 직접 조회를 제안한다. 에이전트는 답을 작성한 뒤 코드와 운영 시스템에서 사실을 확인한다.

인용되었지만 검토되지 않은 노트는 검토 대기열 앞쪽으로 이동하므로 사용자가 먼저 판정한다.
