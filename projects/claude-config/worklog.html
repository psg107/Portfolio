업무일지

업무일지란

아침 스크럼 회의 전에는 전날 한 일을 정리하고, 주마다 한 주 업무를 보고로 정리해야 한다. Jira 티켓과 GitHub 커밋에서 한 일을 매번 다시 찾아야 하므로, 업무일지 스킬(worklog)이 두 작업을 에이전트가 처리하게 한다.

업무일지는 하루 동안 실제로 한 일을 날짜별 파일 하나에 작성한 일간 기록이다. 업무일지 스킬은 업무 기록을 읽어 일간 기록을 작성하고, 일간 기록을 근거로 스크럼 회의에서 읽을 스크럼 파일과 주간 보고를 생성한다.

Claude 데스크톱 앱이 평일 아침마다 실행하는 루틴(worklog-daily)이 업무일지 스킬로 파일을 생성하고, 스크럼 파일의 내용을 Google Docs에 있는 팀 스크럼 문서에 기입한다.

아침 루틴

업무일지 스킬은 지식 수집이 Jira와 GitHub와 Slack에서 내려받은 저장본을 읽어 일간 기록을 작성한다. 수집에 실패한 출처가 있으면 루틴은 해당 날짜의 일간 기록을 보류로 보고하고, 다음 날 루틴이 다시 시도한다.

스크럼 파일

일간 기록에는 에이전트 도구를 다룬 개인 작업처럼 팀 업무가 아닌 일도 기록된다. 그래서 업무일지 스킬은 일간 기록에서 팀 업무만 선택해 오늘 날짜의 스크럼 파일을 작성한다.

스크럼 파일도 일간 기록과 주간 보고처럼 형식 검사 스크립트(worklog-lint.py)를 통과해야 업무일지 폴더에 저장된다.

구분규칙
라벨
  • 항목을 어제 한 일, 오늘 할 일, 공유 라벨로 분류한다.
포함
  • 다이나믹 패키지 업무를 기록한다.
제외
  • 에이전트 도구를 다룬 개인 작업을 제외한다.
  • 동료 PR 승인을 제외한다.
형식 검사
  • 라벨 순서를 검사한다.
  • 항목 형식을 검사한다.

팀 문서 기입

팀 스크럼 문서에는 회의 날짜마다 구역이 있고, 구역 안에 참석자 이름 줄이 있다. 날짜 구역과 이름 줄은 회의 전에 사람이 직접 작성한다.

기입 스크립트(scrum-post.py)는 Google Docs 기록 스크립트(scrum-to-gdoc.py)를 실행한다. 기록 스크립트는 Google Apps Script 웹 앱을 거쳐 사용자 이름 줄 아래에 스크럼 파일의 라벨과 항목을 한 번 기록한다.

다른 참석자도 같은 문서를 수정하므로, 기록 위치는 사용자 이름 줄 아래로 제한한다.

기입 스크립트는 기록 결과에 따라 아래와 같이 대응한다.

기록 결과대응
기록에 성공했다.
  • 기록한 라벨과 줄을 출력한다.
그날 구역이 없거나 여러 개다.
  • 기입하지 않고 문서 맨 위 구역의 날짜를 알린다.
  • 구역은 생성하지 않는다.
사용자 이름 줄이 없거나 여러 개다.
  • 구역 제목이 팀 스크럼 제목이 아니면 대상 아님으로 판정하고 기입을 생략한다.
  • 팀 스크럼 구역이면 기입하지 않는다.
  • 이름 줄은 생성하지 않는다.
문서를 읽은 뒤 쓰기 전에 다른 사람이 문서를 수정했다.
  • 문서를 다시 읽고 재시도한다.
오류 문구가 일시 실패 문구와 일치한다.
  • 재시도한다.
그 밖의 오류가 발생했다.
  • 실패로 종료한다.

재시도는 다른 사람의 문서 수정과 일시 실패를 합쳐 최대 6회다. 대기 시간은 2초에서 시작해 시도마다 2배로 증가하고, 30초를 초과하지 않는다.

재시도 후에도 기입하지 못하면 루틴은 기입 스크립트가 출력한 첫 줄을 완료 보고에 그대로 포함한다.

일시 실패 문구는 아래 오류를 가리킨다.

  • 권한 거절(unauthorized)
  • 웹 앱 응답 파싱 실패
  • 문서 요소 목록 요청 실패
  • Apps Script 호출 횟수 초과와 실행 시간 초과
  • 내부 오류
  • 502와 503과 504 응답
  • 시간 초과

권한 거절은 토큰 문제처럼 보이지만, 권한 거절로 실패한 요청을 같은 토큰으로 바로 다시 보내면 성공한다. 그래서 기입 스크립트는 권한 거절을 웹 앱의 일시 거절로 판단하고 재시도 대상에 포함한다.
